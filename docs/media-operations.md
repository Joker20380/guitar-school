# Загрузка материалов: эксплуатация

Установлено 2026-09-12. Проект: `/opt/apps/guitar-school`, контейнер: `guitar_school_web`.

## Хранение

- `media/` — публичные обложки и фотографии. Nginx обслуживает `/media/` существующим alias. Каталог и изображения должны читаться веб-сервером.
- `private_media/` — учебные документы и видео. Этот каталог нельзя публиковать через alias, staticfiles или CDN. Он находится вне `media/`, корневой каталог имеет права 0700 и принадлежит пользователю приложения.
- Обе директории находятся в существующем bind mount проекта и сохраняются при пересоздании контейнера. Они исключены из Git и Docker build context.
- Резервное копирование должно включать PostgreSQL, `media/` и `private_media/`. Согласуйте копии файлов и базы между собой.
- Удаление/замена записи не удаляет прежний файл физически. Прежний приватный URL больше не сопоставляется с записью и возвращает 404. Очистку сирот проводить отдельно, после проверки ссылок в базе и резервной копии. Публичные изображения по прежним адресам могут оставаться доступны.

## Доступ и ограничения

- Приватные загрузки выдаются через `/courses/files/<name>` с проверкой пользователя, курса, срока, активности и публикации материала/урока. Права staff без соответствующего view/change-разрешения не дают доступа к файлу.
- Скрытие курса в каталоге сохраняет существующую семантику: доступ записанного ученика не отзывается. Для отзыва используйте CourseEnrollment.is_active/access_expires_at.
- Для видео поддерживаются одиночные HTTP byte ranges и HEAD. Документы принудительно скачиваются с `nosniff`; ответы имеют `Cache-Control: private, no-store`.
- Изображение: JPG/JPEG, PNG, WebP до 5 МиБ, проверка содержимого через ImageField/Pillow. Видео: MP4/WebM до 15 МиБ. Вложения: разрешённые расширения в `courses/media.py`, до 15 МиБ.
- Nginx на этом сайте уже настроен на `client_max_body_size 20M`. Это лимит всего запроса. При увеличении лимитов приложения отдельно согласовать лимиты Nginx и время обработки. Большие файлы пока подключаются ссылкой.
- Внешние ресурсы открываются напрямую; их разрешения определяет внешний сервис. Сайт не загружает внешние URL на сервер.

## Проверка и сборка

```sh
python manage.py test --settings=config.test_settings
python manage.py makemigrations courses --check --dry-run --settings=config.test_settings
```

`config.test_settings` использует временную SQLite, локальную почту и тестовый хешер; не запускать с ним рабочий сайт.

Локально и в собранном серверном образе прошли 32 теста, включая 17 новых проверок загрузок и доступа. Браузером проверены восемь страниц/вариантов размера экрана, без ошибок JavaScript и горизонтального переполнения. На рабочем HTTPS проверены multipart-загрузка PDF и изображения через админку, скачивание учеником, диапазон видео, запрет анонимного и отозванного доступа, отсутствие публичного обхода приватного хранилища и ограничение инструкции сотрудниками. Временные записи, сессии и файлы удалены.

Применена миграция `courses.0007_course_cover_file_lesson_video_file_and_more`. В ней также синхронизированы существующие подписи choices с текущим английским языком по умолчанию; значения записей не изменены. Общая проверка миграций обнаруживает ранее существовавшее расхождение подписей choices у `contacts`; миграция для него в эту работу не включена.

Сборка: `guitar-school-web:media-20260912`, затем назначена `guitar-school-web:latest` для стандартного Compose. Образ собран штатным Dockerfile с зависимостями из requirements.txt: Django 5.2.17, Pillow 12.3.0, Python 3.12. Предыдущая сборка использовала Django 5.2.15.

## Резервная копия и восстановление

Перед установкой сохранены исходники изменяемых файлов, manifest контрольных сумм, метаданные старого образа и проверенный `pg_dump -Fc`:

`/opt/apps/guitar-school/backups/media-20260912-121534/`

Старый образ сохранён как `guitar-school-web:before-media-20260912-121534`. При сбое установки предусмотрено восстановление предыдущих исходников и образа с пересборкой статики. Автоматический откат не восстанавливает старую базу поверх новых обращений; добавленная схема совместима с предыдущим кодом. Восстановление базы из дампа — отдельная операция, требующая учёта появившихся после копии данных.

Исходники оставлены в рабочем Git-каталоге; коммит и push не выполнялись.

## Инструкция пользователя

`docs/admin-guide-ru.md` — текстовая версия; `docs/admin-guide-ru.html` — версия с оглавлением и стилями печати. HTML отдаётся только через обёртку `admin.site.admin_view` по `/admin/help/`, ссылка добавлена в шапку админки. Для обновления содержания поддерживать обе версии согласованными. В HTML доступна кнопка печати/сохранения PDF.
